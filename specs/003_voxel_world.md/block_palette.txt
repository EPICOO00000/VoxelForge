==============================================================================
BLOCK PALETTE
==============================================================================

The Block Palette provides the mapping between Universal Block Identifiers
and block definitions.

It minimizes memory usage by ensuring that voxel data stores only compact
numeric identifiers rather than full block descriptions.

==============================================================================

PURPOSE

The Block Palette separates voxel storage from block definitions.

Each voxel stores only a Universal Block Identifier.

Complete block information is stored once inside the Block Palette.

==============================================================================

DESIGN PRINCIPLE

Voxel data must remain as small as possible.

Block definitions must never be duplicated inside individual voxels.

Every unique block definition exists only once inside the palette.

==============================================================================

UNIVERSAL IDENTIFIERS

Every block receives a unique Universal Block Identifier.

Universal IDs are engine-wide identifiers.

They are independent of Blender, Minecraft, Bloxd.io or any other game.

The Universal Identifier never changes while the project is open.

==============================================================================

BLOCK DEFINITIONS

Each block definition may contain information such as:

Display Name

Internal Name

Category

Physical Properties

Rendering Properties

Rotation Capabilities

Metadata Capabilities

Tags

Import Mapping

Export Mapping

Additional engine-independent properties.

==============================================================================

GAME MAPPINGS

Mappings between Universal IDs and game-specific identifiers are stored
outside of the voxel world.

Minecraft mappings.

Bloxd.io mappings.

Future game mappings.

The Voxel World never stores game-specific identifiers.

==============================================================================

PALETTE ACCESS

The Block Palette provides fast lookup in both directions.

Universal ID → Block Definition

Block Name → Universal ID

Game Identifier → Universal ID

Universal ID → Game Identifier

Lookup operations should remain highly efficient.

==============================================================================

MEMORY MODEL

Block definitions are shared.

Multiple voxels referencing the same block always point to the same
definition.

This significantly reduces memory consumption.

==============================================================================

EXTENSIBILITY

New block properties may be added without changing the voxel structure.

Future games may define additional mappings without modifying existing
projects.

==============================================================================

PROJECT STABILITY

Projects should reference Universal IDs only.

Changing external game mappings must not invalidate existing projects.

==============================================================================

RESPONSIBILITIES

The Block Palette is responsible for:

Managing Universal IDs.

Loading block definitions.

Providing lookup services.

Providing game mappings.

Ensuring identifier uniqueness.

Maintaining palette consistency.

==============================================================================

NON RESPONSIBILITIES

The Block Palette does not:

Store voxel data.

Render blocks.

Generate meshes.

Modify worlds.

Perform imports or exports.

==============================================================================

LONG-TERM OBJECTIVE

The Block Palette should allow VoxelForge to support an unlimited number of
games while maintaining a single internal voxel representation.

==============================================================================

END OF BLOCK PALETTE
