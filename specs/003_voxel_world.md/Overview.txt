==============================================================================
VOXEL WORLD OVERVIEW
==============================================================================

The Voxel World is the central data model of the VoxelForge Engine.

It represents the authoritative state of every voxel contained in a project.

Every editing operation ultimately modifies the Voxel World.

No other subsystem owns persistent voxel data.

==============================================================================

PURPOSE

The Voxel World provides a unified representation of voxel information.

It allows every subsystem to interact with voxel data through a common and
consistent interface.

The Voxel World is completely independent from Blender and from any
particular game format.

==============================================================================

SOURCE OF TRUTH

The Voxel World is the only source of truth.

Everything else is generated from it.

Rendered meshes.

Selections.

Exports.

Previews.

Collision data.

Optimization structures.

Temporary caches.

None of these replace the Voxel World.

==============================================================================

RESPONSIBILITIES

The Voxel World is responsible for:

Voxel storage.

Chunk management.

Voxel queries.

Voxel modifications.

Dirty chunk tracking.

Block palette management.

World bounds.

History integration.

Selection integration.

Coordinate conversion.

The Voxel World is not responsible for rendering or exporting.

==============================================================================

DESIGN PRINCIPLES

The Voxel World should remain:

Deterministic.

Memory efficient.

Scalable.

Thread-safe whenever required.

Independent from Blender.

Independent from game formats.

Easy to serialize.

Easy to extend.

==============================================================================

WORLD ORGANIZATION

The world is divided into independent chunks.

Chunks represent the smallest unit of storage,
memory allocation,
mesh generation,
history tracking,
and rendering updates.

No voxel exists outside a chunk.

==============================================================================

VOXEL STORAGE

Voxel information is stored in optimized data structures.

The world never stores Blender objects.

The world never stores meshes.

The world never stores rendering information as authoritative data.

==============================================================================

BLOCK IDENTIFIERS

Every voxel references a universal block identifier.

Game-specific identifiers are handled exclusively by importers and
exporters.

The Voxel World never contains Minecraft-specific or Bloxd-specific block
IDs.

==============================================================================

COORDINATE SYSTEM

The Voxel World uses a global integer coordinate system.

Every voxel position is uniquely identified by its integer coordinates.

Chunks convert global coordinates into local coordinates internally.

==============================================================================

DATA OWNERSHIP

Only the Voxel World may directly modify voxel data.

Other subsystems request modifications through the official public
interfaces.

Direct manipulation of internal storage is prohibited.

==============================================================================

SCALABILITY

The Voxel World is designed to support projects ranging from a few voxels to
worlds containing hundreds of millions of voxels.

Its architecture should scale without requiring structural redesign.

==============================================================================

LONG-TERM OBJECTIVE

The Voxel World should provide a stable, efficient and engine-independent
foundation for every current and future subsystem of VoxelForge.

==============================================================================

END OF VOXEL WORLD OVERVIEW
