==============================================================================
DIRTY CHUNKS
==============================================================================

Dirty Chunks are chunks whose rendered representation is no longer consistent
with the voxel data stored inside the Voxel World.

Dirty tracking allows the engine to update only modified portions of the
world instead of rebuilding the entire scene.

==============================================================================

PURPOSE

Dirty tracking minimizes unnecessary work.

Whenever voxel data changes, only the affected chunks require processing.

This mechanism is fundamental for interactive editing performance.

==============================================================================

DESIGN PRINCIPLES

Dirty tracking must remain:

Automatic.

Deterministic.

Lightweight.

Reliable.

Independent from rendering implementation.

==============================================================================

DIRTY STATE

Each chunk maintains a Dirty State.

A chunk is either:

Clean

or

Dirty

Dirty State represents synchronization status between voxel data and every
derived representation.

==============================================================================

WHEN A CHUNK BECOMES DIRTY

A chunk becomes Dirty whenever voxel data changes.

Examples include:

Brush Operations.

Fill Operations.

Replace Operations.

Import Operations.

Undo.

Redo.

Generator Output.

Plugin Modifications.

Manual Editing.

==============================================================================

NEIGHBOR DEPENDENCIES

Some operations affect neighboring chunks.

Examples include:

Face visibility.

Greedy meshing.

Border voxel modifications.

Whenever required, neighboring chunks must also be marked Dirty.

==============================================================================

DIRTY PROPAGATION

Dirty propagation should remain minimal.

Only chunks whose generated representation may have changed should become
Dirty.

Unnecessary propagation should be avoided.

==============================================================================

DIRTY PROCESSING

Dirty Chunks are processed by the Render System.

The renderer rebuilds only Dirty chunks.

After successful processing the chunk returns to the Clean state.

==============================================================================

MULTIPLE MODIFICATIONS

Multiple voxel modifications performed before rendering should not generate
multiple rebuilds.

Repeated modifications simply keep the chunk Dirty.

==============================================================================

FAILED REBUILDS

If rendering fails, the chunk remains Dirty.

The engine must never incorrectly mark an outdated mesh as synchronized.

==============================================================================

THREAD SAFETY

Dirty State modifications must remain synchronized.

Multiple editing threads must never corrupt Dirty information.

==============================================================================

QUERY OPERATIONS

The Voxel World should efficiently provide:

Iterate Dirty Chunks

Count Dirty Chunks

Clear Dirty State

Mark Dirty

Mark Clean

==============================================================================

PERFORMANCE

Dirty tracking should execute in constant time.

Tracking modifications must introduce negligible overhead compared to voxel
editing itself.

==============================================================================

DESIGN OBJECTIVE

Dirty tracking ensures that only the minimum required amount of work is
performed after every modification.

==============================================================================

END OF DIRTY CHUNKS
