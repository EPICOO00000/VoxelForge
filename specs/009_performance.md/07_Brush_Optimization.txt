==============================================================================
BRUSH OPTIMIZATION
==============================================================================

Brush operations are among the most frequently executed CPU-intensive operations
during voxel editing.

Brush optimization must therefore focus on reducing unnecessary voxel
processing while preserving exact editing behavior.

==============================================================================

DESIGN OBJECTIVES

Brush execution should prioritize:

Fast Interaction.

Predictable Execution Time.

Minimal Memory Allocation.

Efficient Voxel Traversal.

Correct Results.

==============================================================================

AFFECTED REGION

A brush operation should determine the smallest practical region containing the
affected voxels.

Voxels outside that region should not be processed.

==============================================================================

BRUSH MASKS

Brush masks should avoid recomputing identical information unnecessarily.

Reusable masks may be cached when their parameters remain unchanged.

==============================================================================

LARGE BRUSHES

Large brushes may affect significant numbers of voxels.

Their implementation should use efficient traversal and avoid unnecessary
per-voxel overhead.

==============================================================================

SMALL BRUSHES

Small brushes are extremely frequent during interactive editing.

Their execution path should therefore minimize:

Allocations.

Repeated Setup.

Unnecessary Coordinate Conversion.

Redundant Validation.

Unnecessary Event Generation.

==============================================================================

CONTIGUOUS OPERATIONS

When a brush modifies contiguous voxel regions, processing should favor memory
access patterns that improve cache locality.

==============================================================================

BLOCK WRITES

Repeated writes of identical block values should be handled efficiently.

The implementation should avoid unnecessary writes when the target voxel already
contains the requested value.

==============================================================================

BOUNDARY HANDLING

Brushes crossing chunk boundaries must correctly modify every affected chunk.

Neighboring chunks must be marked for downstream updates when required.

==============================================================================

HISTORY

Brush operations must remain compatible with the History system.

Performance optimizations must never bypass required history recording.

==============================================================================

EVENTS

Voxel modification events should represent the logical modification according
to the Event System rules.

Performance optimizations must not silently suppress required notifications.

Where batching is permitted, multiple low-level changes may be represented by
an appropriate higher-level operation without changing observable behavior.

==============================================================================

PARALLELISM

Large independent brush operations may be parallelized when safe.

Parallel brush execution must preserve:

Correct Results.

Determinism.

History Semantics.

Thread Safety.

Chunk Ownership.

==============================================================================

SIMD

Vectorized processing may be used for suitable brush operations when profiling
demonstrates a meaningful benefit.

A simpler implementation should remain available when necessary for portability
or maintainability.

==============================================================================

BRUSH PREVIEW

The visual brush preview should remain separate from expensive world mutation
work.

Preview updates should avoid modifying voxel data.

==============================================================================

BENCHMARKING

Brush performance should be measured across different workloads.

Examples include:

Single Voxel.

Small Brush.

Medium Brush.

Large Brush.

Dense Modification.

Sparse Modification.

Cross-Chunk Modification.

==============================================================================

DESIGN OBJECTIVE

Brush execution should provide immediate and predictable editing feedback while
efficiently scaling from individual voxel changes to very large brush
operations.

==============================================================================

END OF BRUSH OPTIMIZATION
