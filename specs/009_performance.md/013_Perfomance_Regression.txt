==============================================================================
PERFORMANCE REGRESSION
==============================================================================

Performance regressions occur when a change causes an important workload to
perform worse than its established baseline.

VoxelForge should detect and investigate significant regressions before they
become permanent.

==============================================================================

REGRESSION SCOPE

Performance regression may involve:

CPU Time.

GPU Time.

Frame Time.

Memory Usage.

Allocation Count.

Task Throughput.

Import Throughput.

Export Throughput.

Chunk Processing.

Brush Execution.

==============================================================================

BASELINE

A regression comparison requires a valid baseline.

The baseline should correspond to a known VoxelForge version and documented
benchmark configuration.

==============================================================================

COMPARISON

Regression tests should use equivalent workloads.

Changes in:

Hardware.

Operating Environment.

World Size.

Chunk Count.

Worker Count.

Rendering Configuration.

may affect results and must be considered when interpreting measurements.

==============================================================================

SIGNIFICANT REGRESSION

Not every measurement difference represents a meaningful regression.

Small variations may result from normal system or measurement noise.

A regression should be considered significant when the measured degradation is
consistent and relevant to the workload.

==============================================================================

INVESTIGATION

When a significant regression is detected, the responsible change should be
identified where practical.

Profiling should be used to determine whether the regression originates from:

Algorithmic Changes.

Memory Behavior.

Synchronization.

Task Scheduling.

Rendering.

I/O.

Unnecessary Processing.

==============================================================================

CORRECTNESS FIRST

A performance improvement must never be kept if it introduces incorrect voxel
data, broken history, invalid rendering state or other architectural violations.

Correctness remains a required condition for accepting an optimization.

==============================================================================

TRADEOFFS

A change may intentionally increase one cost to improve another.

Examples include:

Higher Memory Usage For Faster Processing.

Higher CPU Usage For Lower GPU Usage.

Additional Precomputation For Faster Interactive Operations.

Such tradeoffs must be measurable and justified by the affected workload.

==============================================================================

REGRESSION DOCUMENTATION

Important performance regressions and their causes may be recorded alongside
benchmark results.

Documentation should explain:

What Changed.

Which Workload Regressed.

How Large The Regression Was.

Why The Change Was Required.

How The Regression Was Addressed Or Accepted.

==============================================================================

RETESTING

After a regression is addressed, the affected benchmark should be executed
again.

Related benchmarks should also be checked when the change affects shared
systems.

==============================================================================

LONG-TERM MONITORING

Performance should be monitored throughout development rather than only before
major releases.

Important workloads should remain representative of real VoxelForge usage.

==============================================================================

DESIGN OBJECTIVE

VoxelForge should prevent significant performance degradation from accumulating
over time while allowing measured and justified tradeoffs when they improve the
overall system.

==============================================================================

END OF PERFORMANCE REGRESSION
