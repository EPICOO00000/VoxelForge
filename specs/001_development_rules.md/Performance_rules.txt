==============================================================================
PERFORMANCE RULES
==============================================================================

Performance is a fundamental objective of the VoxelForge project.

Every feature should be designed with scalability in mind.

Performance considerations must be taken into account from the beginning of
development rather than added later.

==============================================================================

GENERAL PRINCIPLES

Correctness always comes first.

A correct implementation is preferred over a fast but unreliable one.

Once correctness has been achieved, implementations should be optimized
without sacrificing readability or maintainability.

==============================================================================

SCALABILITY

Every new feature should be evaluated for its ability to scale.

Developers should assume that the project may handle:

- millions of voxels
- thousands of chunks
- large terrain generation operations
- complex editing sessions

Solutions that only work efficiently on small datasets should be avoided.

==============================================================================

ALGORITHMIC COMPLEXITY

Developers should always consider algorithmic complexity.

Avoid unnecessary nested loops.

Avoid repeatedly processing the same data.

Avoid algorithms whose complexity grows excessively with world size.

Whenever possible, prefer algorithms with predictable execution time.

==============================================================================

MEMORY USAGE

Memory is a limited resource.

Avoid unnecessary memory allocations.

Avoid unnecessary copies of large data structures.

Temporary allocations should remain as small as possible.

Large objects should not be duplicated unless absolutely necessary.

==============================================================================

REDUNDANT COMPUTATION

Never perform expensive calculations more than necessary.

Reuse existing results whenever possible.

Cache results only when the benefits clearly outweigh the additional memory
usage and maintenance cost.

==============================================================================

RESOURCE AWARENESS

Every implementation should consider the cost of:

CPU time

Memory usage

Disk operations

GPU resources

Large data transfers

Avoid wasting computational resources.

==============================================================================

OPTIMIZATION

Optimization should target measurable bottlenecks.

Do not optimize code without identifying an actual performance problem.

Premature optimization should be avoided.

==============================================================================

MEASUREMENT

Performance improvements should be supported by measurable results whenever
possible.

Avoid assumptions such as:

"I think this is faster."

Instead, rely on profiling, benchmarks or complexity analysis.

==============================================================================

BALANCE

Performance improvements must never significantly reduce:

readability

maintainability

modularity

unless the improvement provides a substantial and measurable benefit.

==============================================================================

LONG-TERM PERFORMANCE

Every implementation should remain efficient as the project grows.

Temporary solutions that cannot scale should be considered technical debt
and replaced when appropriate.

==============================================================================

END OF PERFORMANCE RULES
