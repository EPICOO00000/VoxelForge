TITLE: Performance

PURPOSE:
Defines terminology related to performance throughout VoxelForge.

DEFINITION:
Performance describes the application's ability to process, render, edit, import, export, and manage voxel data efficiently while maintaining responsive interaction.

FRAME TIME:
The time required to produce one rendered frame. Lower frame time generally allows higher frame rates and more responsive viewport interaction.

CPU TIME:
Time spent executing CPU-side operations such as world updates, block processing, chunk generation, file operations, and application logic.

GPU TIME:
Time spent executing GPU-side rendering operations.

MEMORY USAGE:
The amount of system memory and graphics memory consumed by the application and its resources.

CHUNK:
A spatial subdivision of the voxel world used to organize storage, updates, rendering, and processing.

DIRTY CHUNK:
A chunk whose data has changed and therefore requires one or more dependent systems to update it.

CACHE:
A temporary storage mechanism used to avoid repeatedly calculating or loading expensive data.

CACHE INVALIDATION:
The process of marking cached information as outdated after the underlying data changes.

BATCHING:
Combining compatible operations or rendering work to reduce overhead.

CULLING:
Avoiding processing or rendering data that cannot contribute to the current result.

FRUSTUM CULLING:
Discarding chunks or objects outside the camera's visible region.

OCCLUSION CULLING:
Avoiding rendering of geometry that is completely hidden by other geometry when supported by the renderer.

LAZY PROCESSING:
Deferring expensive work until the result is actually required.

ASYNC PROCESSING:
Executing suitable operations outside the main UI/rendering path so that long operations do not unnecessarily block interaction.

MULTITHREADING:
Distributing independent workloads across multiple CPU threads while respecting data ownership and synchronization requirements.

PERFORMANCE BUDGET:
A defined maximum amount of CPU, GPU, memory, or frame-time resources that an operation should normally consume.

PROFILING:
Measuring runtime behavior to identify expensive operations, bottlenecks, memory usage, and performance regressions.

REGRESSION:
A measurable performance degradation introduced by a change.

SCALABILITY:
The ability of the application to continue functioning effectively as world size, structure complexity, number of blocks, or workload increases.

LARGE STRUCTURES:
Large voxel structures must be processed incrementally rather than requiring the entire structure to remain in memory whenever practical.

BLOXD.IO:
Bloxd.io schematic generation must respect the format's maximum of 200 chunks per schematic. Structures larger than this limit must be split into multiple schematic files.

PRIORITY:
Correctness and data integrity take priority over optimization. Performance optimizations must not alter voxel data or produce incompatible output.

MEASUREMENT:
Performance changes should be evaluated using reproducible benchmarks rather than subjective perception alone.
