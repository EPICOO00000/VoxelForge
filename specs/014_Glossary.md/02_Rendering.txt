VOXELFORGE GLOSSARY — RENDERING

Document ID: 014_Glossary / 02_Rendering
Status: Reference
Purpose: Define rendering terminology used throughout VoxelForge.

============================================================
1. RENDERER
============================================================

The Renderer is the subsystem responsible for displaying voxel-world data on screen.

It converts world and block information into renderable geometry and submits that geometry to the graphics system.

============================================================
2. RENDERABLE GEOMETRY
============================================================

Renderable geometry is the mesh or graphical representation generated from voxel data for display.

It should contain only the geometry required for the current rendering context.

============================================================
3. MESH
============================================================

A mesh is a collection of geometric data used to render voxel surfaces.

A voxel mesh may contain:

- vertices;
- indices;
- normals;
- texture coordinates;
- material information;
- optional additional rendering attributes.

============================================================
4. CHUNK MESH
============================================================

A chunk mesh is the renderable geometry associated with a chunk.

Chunk meshes allow VoxelForge to update and render portions of a world independently.

============================================================
5. MESH GENERATION
============================================================

Mesh generation is the process of converting voxel/block data into renderable geometry.

The process should avoid generating faces that cannot be seen.

============================================================
6. FACE CULLING
============================================================

Face culling is the removal of voxel faces that do not need to be rendered.

For example, a face completely enclosed by another opaque block normally does not need to be included in the visible mesh.

============================================================
7. OCCLUSION
============================================================

Occlusion occurs when one object or voxel surface hides another from the camera.

Occlusion techniques reduce unnecessary rendering work by avoiding geometry that cannot contribute to the final image.

============================================================
8. FRUSTUM CULLING
============================================================

Frustum culling determines whether an object or chunk lies outside the camera's visible volume.

Objects completely outside the view frustum can be skipped.

============================================================
9. LOD
============================================================

LOD means Level of Detail.

A LOD system displays different levels of geometric detail depending on factors such as distance from the camera.

VoxelForge may use LOD techniques in future or optimized rendering paths where appropriate.

============================================================
10. DRAW CALL
============================================================

A draw call is a command issued to the graphics API to render geometry.

Reducing unnecessary draw calls can improve rendering performance.

============================================================
11. BATCHING
============================================================

Batching combines compatible rendering work so that multiple objects or surfaces can be processed with fewer graphics operations.

VoxelForge should prefer efficient batching where it does not compromise editing responsiveness or visual correctness.

============================================================
12. MATERIAL
============================================================

A material defines how a rendered surface should appear.

It may reference:

- textures;
- shaders;
- transparency settings;
- lighting properties;
- other rendering parameters.

============================================================
13. TEXTURE
============================================================

A texture is image data applied to rendered geometry.

Textures may represent:

- block surfaces;
- UI elements;
- icons;
- material properties;
- other visual assets.

============================================================
14. UV COORDINATES
============================================================

UV coordinates define how a texture is mapped onto a surface.

Voxel faces commonly use UV coordinates to select the appropriate portion of a block texture.

============================================================
15. SHADER
============================================================

A shader is a GPU-executed program used during rendering.

Shaders may determine:

- vertex transformation;
- surface appearance;
- lighting;
- transparency;
- post-processing effects.

============================================================
16. VERTEX
============================================================

A vertex is a point in geometric data.

A rendered voxel mesh may associate each vertex with attributes such as position, normal and texture coordinates.

============================================================
17. INDEX BUFFER
============================================================

An index buffer contains references used to construct geometric primitives from vertices.

Index buffers can reduce duplicated vertex data and improve rendering efficiency.

============================================================
18. TRANSPARENCY
============================================================

Transparency allows background or other geometry to remain partially visible through a surface.

Transparent and translucent blocks generally require different rendering treatment from fully opaque blocks.

============================================================
19. ALPHA
============================================================

Alpha is a value commonly used to represent opacity.

An alpha value may influence how a pixel or material is blended with the background.

============================================================
20. BACKFACE CULLING
============================================================

Backface culling removes polygon faces that face away from the camera when those faces are known to be unnecessary.

It reduces rendering workload.

============================================================
21. LIGHTING
============================================================

Lighting determines how surfaces are visually illuminated.

VoxelForge rendering may use block/world lighting information depending on the supported rendering model.

============================================================
22. AMBIENT OCCLUSION
============================================================

Ambient occlusion is a visual technique that approximates reduced ambient light in areas where geometry is closely surrounded by other geometry.

It can improve depth perception in voxel environments.

============================================================
23. SHADOW
============================================================

A shadow is a region receiving reduced illumination because an object blocks a light source.

Shadow rendering can be computationally expensive and must be implemented according to the renderer's performance constraints.

============================================================
24. CAMERA
============================================================

The camera defines the user's viewpoint into the voxel world.

It controls values such as:

- position;
- orientation;
- projection;
- view distance;
- field of view.

============================================================
25. VIEW FRUSTUM
============================================================

The view frustum is the volume of space potentially visible through the camera.

Frustum culling uses this volume to determine which objects or chunks require rendering.

============================================================
26. VIEW DISTANCE
============================================================

View distance determines how far from the camera world geometry remains eligible for rendering.

Reducing view distance can significantly reduce rendering workload in large worlds.

============================================================
27. GPU
============================================================

The GPU is the graphics processing unit responsible for executing graphics workloads.

VoxelForge should use the GPU efficiently while avoiding unnecessary synchronization with the CPU.

============================================================
28. CPU-GPU SYNCHRONIZATION
============================================================

CPU-GPU synchronization occurs when CPU execution must wait for GPU work or vice versa.

Unnecessary synchronization can cause stalls and reduce frame rate.

============================================================
29. FRAME
============================================================

A frame is one complete rendered image produced for display.

Frame time is the amount of time required to produce a frame.

============================================================
30. FRAME TIME
============================================================

Frame time is a key rendering-performance measurement.

Lower frame time generally allows a higher frame rate.

============================================================
31. FPS
============================================================

FPS means Frames Per Second.

It represents how many frames are displayed or rendered per second.

FPS alone should not be treated as the only performance metric; frame time and consistency are also important.

============================================================
32. FRAME TIME SPIKE
============================================================

A frame time spike occurs when one frame takes significantly longer than neighboring frames.

Spikes can cause visible stuttering even when average FPS appears acceptable.

============================================================
33. RENDER DISTANCE
============================================================

Render distance defines the maximum area around the camera considered for rendering.

It may be different from world loading distance or simulation distance.

============================================================
34. RENDER QUEUE
============================================================

A render queue is a collection of rendering-related tasks waiting to be processed.

Examples include:

- chunk mesh generation;
- mesh uploads;
- texture operations;
- GPU resource updates.

============================================================
35. MESH INVALIDATION
============================================================

Mesh invalidation occurs when world data changes and the existing mesh is no longer valid.

The affected chunk must be scheduled for mesh regeneration or another appropriate update.

============================================================
36. DIRTY CHUNK
============================================================

A dirty chunk is a chunk whose renderable representation is no longer synchronized with its underlying voxel data.

Dirty chunks require an appropriate update before their visual representation is considered current.

============================================================
37. RENDER CACHE
============================================================

A render cache stores reusable rendering data to avoid regenerating or re-uploading unchanged resources unnecessarily.

Cache invalidation must be deterministic and safe.

============================================================
38. RENDERING OPTIMIZATION
============================================================

Rendering optimization is the process of reducing rendering cost while preserving required visual correctness.

Typical techniques include:

- face culling;
- frustum culling;
- batching;
- chunk meshing;
- caching;
- LOD;
- reduced draw calls.

============================================================
39. VISUAL CORRECTNESS
============================================================

Visual correctness means that the rendered result accurately represents the underlying voxel and block state according to the rendering specification.

Performance optimizations must not introduce incorrect visible geometry.
