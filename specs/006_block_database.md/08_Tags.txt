==============================================================================
BLOCK TAGS
==============================================================================

Block Tags provide logical grouping for Block Definitions.

Tags describe characteristics shared by multiple blocks without creating
inheritance relationships.

A Block Definition may belong to multiple Tags simultaneously.

==============================================================================

PURPOSE

Tags allow engine systems to query groups of blocks using semantic meaning
instead of explicit identifiers.

Systems should reason about categories rather than individual blocks whenever
possible.

==============================================================================

DESIGN PRINCIPLES

Tags must remain:

Lightweight.

Deterministic.

Data Driven.

Extensible.

Game Independent.

==============================================================================

COMMON TAGS

Examples include:

Solid.

Transparent.

Liquid.

Natural.

Artificial.

Stone.

Wood.

Metal.

Vegetation.

Decoration.

Interactive.

Replaceable.

Climbable.

Emissive.

==============================================================================

CUSTOM TAGS

Users and Plugins may register additional Tags.

Custom Tags follow the same validation rules as built-in Tags.

==============================================================================

MULTIPLE TAGS

A Block Definition may belong to any number of Tags.

Example:

Oak Planks

↓

Wood

Construction

Flammable

Solid

==============================================================================

LOOKUP

The Block Registry should provide efficient lookup by Tag.

Tag queries should remain efficient even for very large Block Databases.

==============================================================================

DEPENDENCIES

Engine systems should rely on Tags whenever possible instead of maintaining
hardcoded block lists.

==============================================================================

VERSIONING

Tags should remain stable across engine versions whenever practical.

==============================================================================

DESIGN OBJECTIVE

Tags provide a flexible semantic classification system allowing engine
features to remain generic, extensible and independent from specific block
identifiers.

==============================================================================
