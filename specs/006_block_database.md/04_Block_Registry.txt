==============================================================================
BLOCK REGISTRY
==============================================================================

The Block Registry manages every Block Definition known by the engine.

It is the single authority responsible for block registration and lookup.

==============================================================================

PURPOSE

The Block Registry provides fast and reliable access to Block Definitions
throughout the entire engine.

==============================================================================

DESIGN PRINCIPLES

The Registry must remain:

Centralized.

Deterministic.

Thread Safe.

Fast.

Extensible.

==============================================================================

RESPONSIBILITIES

The Registry is responsible for:

Registering Block Definitions.

Validating identifiers.

Providing lookup services.

Managing plugin registrations.

Preventing duplicate IDs.

Preventing duplicate names.

==============================================================================

REGISTRATION

Every Block Definition must be registered exactly once.

Registration occurs during engine initialization or plugin loading.

==============================================================================

LOOKUP METHODS

The Registry should support lookup by:

Universal Block ID.

Internal Name.

Display Name.

Game Mapping.

Tags.

==============================================================================

VALIDATION

Registration must reject:

Duplicate IDs.

Duplicate internal names.

Invalid definitions.

Corrupted metadata.

==============================================================================

PLUGIN REGISTRATION

Plugins may register additional Block Definitions.

Plugin registrations follow the same validation rules as built-in blocks.

==============================================================================

PERFORMANCE

Lookup operations should execute in constant time.

Registration speed is less important than lookup performance.

==============================================================================

LIFETIME

The Registry exists for the entire lifetime of the engine.

Definitions remain available until engine shutdown.

==============================================================================

DESIGN OBJECTIVE

The Block Registry provides a reliable, scalable and deterministic catalogue
of every Block Definition used by VoxelForge.

==============================================================================

END OF BLOCK REGISTRY
