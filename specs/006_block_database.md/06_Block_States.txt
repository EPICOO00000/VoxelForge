==============================================================================
BLOCK STATES
==============================================================================

Block States describe finite variations of a Block Definition.

States modify the behavior or appearance of a block without creating a new
Universal Block Definition.

==============================================================================

PURPOSE

States prevent unnecessary duplication of Block Definitions while supporting
complex block behavior.

==============================================================================

DESIGN PRINCIPLES

States must remain:

Deterministic.

Validated.

Finite.

Serializable.

Game Independent.

==============================================================================

EXAMPLES

Possible Block States include:

Orientation.

Rotation.

Axis.

Open / Closed.

Powered.

Waterlogged.

Age.

Growth Stage.

Connection State.

==============================================================================

STATE MODEL

Each Block Definition explicitly defines the states it supports.

Unsupported states are invalid.

==============================================================================

VALID VALUES

Every state defines a finite list of valid values.

Examples:

True / False.

North / South / East / West.

0 → 15.

==============================================================================

DEFAULT STATE

Every state has one default value.

New voxels always begin with default states unless explicitly overridden.

==============================================================================

IMPORT

Importers translate game-specific states into Universal States.

==============================================================================

EXPORT

Exporters convert Universal States into the target game's representation.

==============================================================================

VALIDATION

Invalid state combinations must never be stored.

==============================================================================

PERFORMANCE

State lookup should require minimal memory overhead.

==============================================================================

DESIGN OBJECTIVE

Block States provide flexible block variation while preserving a compact and
consistent block database.

==============================================================================

END OF BLOCK STATES
