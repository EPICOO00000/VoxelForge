==============================================================================
GAME MAPPINGS
==============================================================================

Game Mappings define how Universal Block Definitions correspond to blocks in
specific voxel games.

Mappings isolate game-specific information from the engine.

The Core never accesses game identifiers directly.

==============================================================================

PURPOSE

The Mapping System allows a single Voxel World to be exported to multiple
games while preserving semantic meaning whenever possible.

==============================================================================

DESIGN PRINCIPLES

Mappings must remain:

Game Independent.

Data Driven.

Version Aware.

Deterministic.

Replaceable.

==============================================================================

MAPPING MODEL

Each Universal Block Definition may contain zero or more Game Mappings.

Each Game Mapping belongs to exactly one target game.

==============================================================================

SUPPORTED GAMES

Examples include:

Minecraft.

Bloxd.

Minetest.

Vintage Story.

Future Games.

The engine must never assume a fixed list of supported games.

==============================================================================

MAPPING CONTENT

A Game Mapping may contain:

Target Game.

Game Version.

Game Block Identifier.

Block State Conversion.

Metadata Conversion.

Additional Conversion Rules.

==============================================================================

VERSION SUPPORT

Different versions of the same game may require different mappings.

Mappings should specify their compatible version range.

==============================================================================

MISSING MAPPINGS

If no valid mapping exists:

The exporter should apply its configured fallback strategy.

The engine itself must never invent mappings.

==============================================================================

DATA STORAGE

Mappings should be stored in external configuration files.

The engine should allow mappings to be updated without recompilation.

==============================================================================

PLUGIN SUPPORT

Plugins may register additional mappings.

Plugin mappings follow the same validation rules as built-in mappings.

==============================================================================

DESIGN OBJECTIVE

Game Mappings provide a flexible translation layer allowing VoxelForge to
support multiple voxel games without modifying the Core.

==============================================================================

END OF GAME MAPPINGS
