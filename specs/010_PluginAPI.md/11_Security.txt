==============================================================================
PLUGIN API — SECURITY
==============================================================================

VoxelForge plugins execute as extensions of the application and must therefore
operate within the permissions, validation and isolation rules defined by the
Plugin Runtime.

Security must protect the application, project data, world data and users while
still allowing legitimate plugin functionality.

==============================================================================

PLUGIN TRUST

Plugins must be treated as external code.

The application must not assume that a plugin is safe simply because it was
installed locally or was previously enabled.

Plugin metadata and requested capabilities must be validated before activation.

==============================================================================

PERMISSIONS

Plugins should request only the permissions required for their functionality.

Potential capabilities may include:

World Access.

File Access.

Network Access.

UI Integration.

Rendering.

External Process Access where explicitly supported.

Plugins must not silently obtain capabilities outside their declared or granted
permissions.

==============================================================================

WORLD DATA

Plugins modifying voxel worlds must use the documented APIs.

Direct manipulation of private storage is forbidden.

World modifications must preserve:

History.

Events.

Chunk State.

Block Validity.

Rendering Invalidation.

==============================================================================

FILE ACCESS

File operations must follow the permissions and path restrictions provided by
the Plugin Runtime.

Plugins must not arbitrarily overwrite application files, project files or
another plugin's private data.

User-selected files and explicit plugin data directories should be preferred
when available.

==============================================================================

NETWORK ACCESS

Network functionality must be explicitly permitted when the API supports
network permissions.

Plugins must not assume unrestricted network access.

Network operations must not expose project or world data without appropriate
authorization.

==============================================================================

INPUT VALIDATION

All plugin-provided data must be validated before entering core systems.

This includes:

Block Identifiers.

Coordinates.

Dimensions.

File Paths.

Configuration Values.

Import Data.

Export Options.

UI Input.

Event Payloads.

==============================================================================

RESOURCE LIMITS

Plugins must not intentionally or accidentally consume unbounded resources.

Large operations should respect available limits for:

Memory.

CPU.

Disk Space.

Task Count.

World Size.

Rendering Resources.

==============================================================================

CODE EXECUTION

Plugin-provided code must remain subject to the capabilities granted by the
runtime and the security model of the host platform.

Plugins must not attempt to bypass VoxelForge permissions or sandbox mechanisms.

==============================================================================

CREDENTIALS AND SECRETS

Plugins must not store credentials or secrets in world files, schematic files,
logs or publicly accessible plugin configuration unless explicitly required and
secured by the platform.

Sensitive information must not be exposed through diagnostic output.

==============================================================================

PLUGIN ISOLATION

A plugin failure or malicious operation should be isolated from unrelated
plugins and core systems where technically possible.

The runtime should prevent stale plugin callbacks from executing after the
plugin has been unloaded.

==============================================================================

IMPORT SECURITY

Imported files must be treated as untrusted input.

Importers must validate file structure before creating world data.

Malformed or unexpectedly large files must not cause uncontrolled memory
allocation or world corruption.

==============================================================================

EXPORT SECURITY

Exporters must validate output paths and options before writing files.

An exporter must not silently overwrite unrelated user data.

Bloxd.io `.bloxdschem` exports must respect the 200-chunk maximum per schematic
and split larger exports into multiple files.

==============================================================================

MINECRAFT COMPATIBILITY

Minecraft data must be validated before being converted into VoxelForge world
data.

Unsupported or invalid data must be handled explicitly rather than silently
producing corrupt blocks.

==============================================================================

UI SECURITY

Plugin UI must not impersonate privileged VoxelForge dialogs or mislead users
about operations being performed.

Destructive operations should use the appropriate confirmation mechanisms.

==============================================================================

EVENT SECURITY

Plugins must not abuse high-frequency events to create uncontrolled resource
usage.

Event handlers must respect event ownership and access restrictions.

==============================================================================

LOGGING

Security-sensitive information must not be written to logs unnecessarily.

Plugin failures should provide enough diagnostic information to debug the
problem without exposing secrets or private user data.

==============================================================================

UPDATES

Plugin updates must preserve compatibility and permission expectations.

A plugin update that requests additional capabilities should require the
appropriate permission handling rather than silently inheriting new privileges.

==============================================================================

DESIGN OBJECTIVE

The Plugin Security model protects VoxelForge and its users from unsafe plugin
behavior while maintaining controlled access to world, UI, rendering,
import/export and other documented APIs.

==============================================================================

END OF SECURITY
