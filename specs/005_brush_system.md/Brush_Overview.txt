==============================================================================
BRUSH SYSTEM OVERVIEW
==============================================================================

The Brush System is the primary interaction mechanism between the user and
the Voxel World.

Every modification performed inside the editor is executed through a Brush.

Brushes represent editing tools rather than rendering tools.

They never interact directly with Blender meshes.

==============================================================================

PURPOSE

The Brush System translates user actions into deterministic voxel
modifications.

It provides a consistent editing experience regardless of the brush type,
world size or export target.

==============================================================================

DESIGN PHILOSOPHY

Every brush follows exactly the same execution pipeline.

Brushes differ only by:

Shape.

Behavior.

Parameters.

Everything else is handled by the Brush Engine.

This ensures consistency, extensibility and maintainability.

==============================================================================

DESIGN PRINCIPLES

The Brush System must remain:

Deterministic.

Modular.

Stateless whenever practical.

Game Independent.

Renderer Independent.

Extensible.

==============================================================================

UNIVERSAL EDITING

Brushes modify the Universal Voxel World.

They never manipulate:

Minecraft blocks.

Bloxd blocks.

Export formats.

Rendering geometry.

Blender objects.

==============================================================================

BRUSH RESPONSIBILITIES

A Brush is responsible only for describing:

Its editing behavior.

Its editable parameters.

Its execution rules.

It is not responsible for:

Voxel storage.

History.

Rendering.

Task scheduling.

Importing.

Exporting.

==============================================================================

BRUSH ENGINE

Every brush executes through the Brush Engine.

The Brush Engine guarantees identical execution rules for every editing tool.

Brushes never modify the world directly.

==============================================================================

CONSISTENCY

Two brushes receiving identical inputs must always produce identical voxel
changes.

Random behavior must always be explicitly controlled by parameters.

==============================================================================

USER EXPERIENCE

Every brush should feel predictable.

Users should never need to understand internal implementation details.

Brush behavior should remain intuitive.

==============================================================================

EXTENSIBILITY

New brushes should be added by implementing new Brush Behaviors or Brush
Shapes.

Existing engine code should rarely require modification.

==============================================================================

FUTURE COMPATIBILITY

Future editing tools should integrate naturally into the Brush System without
changing existing interfaces.

==============================================================================

DESIGN OBJECTIVE

The Brush System should provide a simple, powerful and scalable editing
framework capable of supporting every future voxel editing tool.

==============================================================================

END OF BRUSH SYSTEM OVERVIEW
