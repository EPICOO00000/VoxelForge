==============================================================================
BRUSH PARAMETERS
==============================================================================

Brush Parameters define the configurable properties controlling Brush
execution.

Parameters describe Brush behavior without modifying the execution pipeline.

Every Brush exposes its functionality exclusively through Parameters.

==============================================================================

PURPOSE

Parameters allow Brushes to remain generic while supporting a wide range of
editing behaviors.

Changing Parameters modifies Brush behavior without requiring different Brush
implementations.

==============================================================================

DESIGN PRINCIPLES

The Parameter System must remain:

Deterministic.

Strongly Typed.

Self-validating.

Serializable.

Extensible.

Independent from Blender UI.

==============================================================================

PARAMETER MODEL

Every Parameter is represented by a strongly typed object.

Parameters are not simple variables.

Each Parameter contains both its value and its metadata.

==============================================================================

PARAMETER PROPERTIES

Every Parameter should define:

Unique Identifier.

Display Name.

Description.

Data Type.

Default Value.

Current Value.

Minimum Value.

Maximum Value.

Step Size.

Precision.

Category.

Visibility Rules.

Validation Rules.

==============================================================================

SUPPORTED DATA TYPES

The Parameter System should support:

Boolean.

Integer.

Float.

String.

Enumeration.

Vector2.

Vector3.

Color.

Curve.

Texture Reference.

Block Reference.

Future custom data types.

==============================================================================

VALIDATION

Every Parameter validates its value before execution.

Invalid values must never reach the Brush Engine.

Validation should detect:

Out-of-range values.

Invalid types.

Missing references.

Illegal combinations.

==============================================================================

DEPENDENCIES

Parameters may depend on other Parameters.

Examples include:

Radius enabled only for volumetric Brushes.

Height visible only for Cylinders.

Noise Seed visible only when Random Mode is enabled.

Dependency rules should remain declarative.

==============================================================================

GROUPING

Parameters may be organized into logical groups.

Examples include:

General.

Shape.

Behavior.

Falloff.

Advanced.

Debug.

==============================================================================

PRESETS

Parameter collections may be stored as Presets.

Loading a Preset restores every Parameter value simultaneously.

==============================================================================

SERIALIZATION

Parameters must support deterministic serialization.

Serialized Parameters should remain version compatible whenever practical.

==============================================================================

UNDO SUPPORT

Parameter modifications may optionally participate in the History System.

==============================================================================

USER INTERFACE

The Parameter System never creates Blender UI directly.

The UI automatically reflects Parameter definitions.

Brush code must never manually construct interface layouts.

==============================================================================

PLUGINS

Plugins may register additional Parameters.

Custom Parameters must behave exactly like built-in Parameters.

==============================================================================

PERFORMANCE

Parameter validation should remain lightweight.

Reading Parameter values should require minimal overhead.

==============================================================================

DETERMINISM

Identical Parameter sets must always produce identical Brush execution.

==============================================================================

FUTURE FEATURES

Future implementations may support:

Animated Parameters.

Expression-driven Parameters.

Driver Systems.

Node-controlled Parameters.

Parameter Linking.

==============================================================================

DESIGN OBJECTIVE

The Parameter System should provide a universal, extensible and strongly
typed configuration framework capable of supporting every current and future
editing tool.

==============================================================================

END OF BRUSH PARAMETERS
