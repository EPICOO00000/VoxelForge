==============================================================================
IMPORT / EXPORT SYSTEM OVERVIEW
==============================================================================

The Import / Export System is responsible for converting data between
VoxelForge's internal representation and external voxel formats.

It provides a strict separation between the engine and every supported game.

The Import / Export System never modifies the Voxel World architecture.

==============================================================================

SUPPORTED TARGETS

The first supported ecosystems are:

• Minecraft
• Bloxd.io

The architecture must remain open to future voxel games without requiring
changes to the Core.

==============================================================================

PURPOSE

The Import / Export System enables interoperability between VoxelForge and
external voxel editors, games and file formats.

All conversions pass through the Universal Block Database.

The Core never manipulates game-specific identifiers.

==============================================================================

DESIGN PRINCIPLES

The Import / Export System must remain:

Game Independent.

Modular.

Deterministic.

Data Driven.

Version Aware.

Extensible.

==============================================================================

RESPONSIBILITIES

The system is responsible for:

Importing supported file formats.

Exporting supported file formats.

Universal Block ID conversion.

Block State conversion.

Metadata conversion.

Version compatibility.

Validation.

Error reporting.

Automatic project splitting when required by target formats.

==============================================================================

SUPPORTED FORMATS

Initial implementation should support:

Minecraft Schematic.

Minecraft Litematic.

Bloxd.io .bloxdschem.

Additional formats should integrate through new Importer and Exporter
implementations without modifying existing code.

==============================================================================

BLOCK DATABASE

Every conversion must pass through the Universal Block Database.

No Importer or Exporter may perform direct game-to-game translation.

Example:

Minecraft

↓

Universal Block Database

↓

Bloxd.io

Never:

Minecraft

↓

Bloxd.io

==============================================================================

FORMAT LIMITATIONS

Some target formats impose structural limitations.

Example:

Bloxd.io schematics currently support a practical maximum of approximately
200 chunks per file.

When exporting larger worlds, the Export System must automatically split the
world into multiple .bloxdschem files while preserving their relative
positions.

These limitations belong to individual Exporters and never affect the Core.

==============================================================================

DESIGN OBJECTIVE

The Import / Export System provides a scalable, extensible and reliable bridge
between the internal engine representation and every supported voxel format.

==============================================================================

END OF IMPORT / EXPORT SYSTEM OVERVIEW
