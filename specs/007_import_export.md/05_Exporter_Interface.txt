==============================================================================
EXPORTER INTERFACE
==============================================================================

Every Exporter implements the common Exporter Interface.

The interface defines the contract used by the engine to generate external
voxel files.

==============================================================================

PURPOSE

The Exporter Interface allows every supported game format to share the same
export workflow while keeping implementation details isolated.

==============================================================================

DESIGN PRINCIPLES

Every Exporter must be:

Independent.

Stateless.

Reusable.

Deterministic.

Version Aware.

==============================================================================

GENERAL WORKFLOW

Receive Export Request

↓

Validate World

↓

Iterate Chunks

↓

Convert Blocks

↓

Convert States

↓

Convert Metadata

↓

Serialize Target Format

↓

Write Output File

↓

Return Export Result

==============================================================================

WORLD ACCESS

Exporters access the Voxel World only through its public interfaces.

Direct memory access is forbidden.

==============================================================================

BLOCK CONVERSION

Every Universal Block ID must be translated through the Block Database.

Exporters must never contain hardcoded block definitions.

==============================================================================

FORMAT LIMITATIONS

Each Exporter is responsible for respecting the limitations of its target
format.

Example:

The Bloxd.io Exporter must automatically split exports exceeding the maximum
supported chunk count per .bloxdschem file.

Such limitations must never influence the internal engine architecture.

==============================================================================

FILE GENERATION

Exporters should generate complete output before replacing existing files
whenever practical.

Failed exports must never corrupt previous files.

==============================================================================

EXTENSIBILITY

Supporting a new export format should require implementing only a new
Exporter.

Existing exporters must remain untouched.

==============================================================================

DESIGN OBJECTIVE

The Exporter Interface provides a stable, extensible and deterministic
foundation for every future export format supported by VoxelForge.

==============================================================================

END OF EXPORTER INTERFACE
