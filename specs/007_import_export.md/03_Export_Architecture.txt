==============================================================================
EXPORT ARCHITECTURE
==============================================================================

The Export Architecture defines how Voxel Worlds are converted into external
voxel formats.

Each Exporter translates the internal representation into one specific target
format.

DESIGN PRINCIPLES

Every Exporter must remain:

Independent.

Stateless.

Deterministic.

Reusable.

==============================================================================

BLOCK DATABASE

Exporters obtain every conversion through the Universal Block Database.

Direct game-to-game mappings are forbidden.

==============================================================================

BLOXD.IO EXPORT

The Bloxd.io exporter follows the reverse-engineered Schema Version 0 format.

Important characteristics include:

• Fixed chunk size of 32 × 32 × 32 voxels.
• Avro binary serialization.
• Run-Length Encoding (RLE).
• Unsigned LEB128 integer encoding.
• Chunk-local voxel ordering:
  local_x × 1024 + local_y × 32 + local_z.

These implementation details belong exclusively to the Bloxd Exporter and are
completely hidden from the Core.

==============================================================================

AUTOMATIC FILE SPLITTING

Bloxd.io currently supports approximately 200 chunks per .bloxdschem file.

If a Voxel World exceeds this limit, the exporter must automatically split
the world into multiple .bloxdschem files.

Each generated file must preserve its absolute chunk coordinates so the
complete world can be reconstructed correctly.

Splitting is entirely transparent to the user whenever possible.

==============================================================================

VALIDATION

Every exported file should be validated before serialization.

==============================================================================

ERROR HANDLING

Export failures must never modify the original Voxel World.

Partial files should never remain after a failed export.

==============================================================================

DESIGN OBJECTIVE

The Export Architecture provides deterministic and extensible conversion from
the internal engine representation to external voxel formats while isolating
all format-specific constraints inside individual Exporters.
